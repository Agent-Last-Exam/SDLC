### R08 · API 支持可配置的根 mutation 数量上限 `GRAPHQL_MUTATION_COUNT_LIMIT`
- 来源：Instruction："Keep the backend API and Dashboard behavior consistent." 推导依据：运行时 `/opt/runtime/services.sh` 以 `GRAPHQL_MUTATION_COUNT_LIMIT=4 uvicorn saleor.asgi:application …` 启动 API，注释为 "Dashboard VariantUpdate sends four root mutations. Scope the deployment limit to the API process; pytest retains upstream settings and validator coverage"。这说明 3.23 Core 有对应的设置项和校验器，而当前 Core 的 `settings.py` 中只有 `GRAPHQL_QUERY_MAX_COMPLEXITY`。Dashboard 文档中根 mutation 数量的统计：`VariantUpdate` 4 个，`MenuUpdate` 3 个，`CollectionAssignProduct`、`OrderSettingsUpdate`、`ShopSettingsUpdate`、`UpdateMetadata`、`UpdatePrivateMetadata` 各 2 个。
- 优先级：P0
- 需求描述：
  - Core 新增设置 `GRAPHQL_MUTATION_COUNT_LIMIT`，从同名环境变量读取整数。请求在执行前做校验：单个 mutation 操作中根级 mutation 字段的数量超过上限时，整个请求被拒绝，不执行其中任何 mutation，返回标准 GraphQL `errors`，错误信息说明超限及上限值。
  - 计数规则：按操作中根选择集里的 mutation 字段计数，同一字段使用不同 alias 各计一次；通过片段展开到根的字段同样计入。只统计本次实际执行的操作，查询（query）与订阅不受影响。
  - 未设置环境变量时采用上游默认值（具体数值见 §5 Q4）；按 Saleor 现有惯例，值为 `0` 表示关闭限制。
  - 校验错误的处理与 query cost 校验一致：在 API 响应中可识别，不产生副作用，并记录可观测性信息（参照 `QUERY_COST_FAILED_OPERATION` 的处理方式）。
  - Dashboard 方面：在 `GRAPHQL_MUTATION_COUNT_LIMIT=4` 的部署下，Dashboard 所有现有文档都不得超限，最多的 `VariantUpdate` 为 4。新增或修改的 Dashboard mutation 文档不得超过 4 个根 mutation。

  - AC-08-3：设置 `GRAPHQL_MUTATION_COUNT_LIMIT=1`，发送包含 5 个根字段的 query，正常返回，不受限制。
  - AC-08-4：设置 `GRAPHQL_MUTATION_COUNT_LIMIT=0`，发送包含 10 个根 mutation 的请求，不因数量被拒绝。
  - AC-08-5：在运行时环境（`GRAPHQL_MUTATION_COUNT_LIMIT=4`）中，于 Dashboard 编辑一个商品变体的属性、价格、库存和元数据后点击保存，出现成功通知（`[data-test-type="success"]`），刷新后修改均已保存。

**产品决策**

- D1：Adyen、NP Atobarai 采取"移除插件、保留存量数据可读"的策略（R05）。依据是目标依赖清单移除了它们唯一依赖的 SDK，而 Instruction 禁止联网安装，也不允许用桩代码冒充生产功能。
- D2：根 mutation 数量限制作为 API 层通用能力实现（R08），Dashboard 侧保证所有文档不超过 4 个根 mutation，不另行拆分 `VariantUpdate`。
- D3：`@saleor/sdk` 的替代采用 Dashboard 内部实现（R11），沿用 `src/graphql/client.ts` 注释中的既定方向。
- D4：通知改用 sonner 时，以 E2E 选择器 `data-test-type` 与 `useNotifier` API 不变作为硬约束（R13）。

**假设**

- A1：上游 3.23 中，`AppExtension.mountName`/`targetName` 的值为大写枚举名，`settings` 的结构为 `{newTabTarget|widgetTarget: {method}}`。依据是 Dashboard 现有代码与单测数据，例如 `mountName: "PRODUCT_OVERVIEW_CREATE"`、`settings: { newTabTarget: { method: "POST" } }`。
- A2：`GRAPHQL_MUTATION_COUNT_LIMIT` 的语义是"单个操作的根 mutation 字段数上限"。依据是运行时注释 "VariantUpdate sends four root mutations"。
