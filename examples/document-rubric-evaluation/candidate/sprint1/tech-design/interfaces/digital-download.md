# 历史数字权益兼容下载协议

版本：v1
责任：后端技术设计
依据：PRD 1.0，R07

## 1. 边界

本协议保留 Base 已有 token 下载 HTTP 边界，仅服务切换前已购权益；它不是新数字分发产品，也不提供创建、更新或重新签发权益的公开接口。GraphQL 中 `DigitalContent`、`DigitalContentUrl` 及相关操作按 `target-schema.graphql` 退出。

## 2. 请求

- 方法：`GET`
- 路径：沿用 Base 的数字下载 token 路径，不改变已签发 URL 的 path 结构。
- 身份：URL token 是随机能力凭证；不接受对象 ID 替代 token，不通过查询参数放宽次数、期限或订单归属。
- 重定向：成功时由现有下载视图返回受保护文件响应或短期存储签名地址；不得返回永久公开媒体地址。

## 3. 判定与响应

| 场景 | HTTP 结果 | 语义 |
| --- | --- | --- |
| token 有效且未耗尽 | `200` 或现有受控文件重定向 | 以原子条件更新增加一次下载计数后返回历史快照文件。 |
| token 不存在 | `404` | 不区分“不存在”和“不属于请求者”，避免对象枚举。 |
| 已过期或次数耗尽 | `410` | 不增加计数，不返回文件。 |
| 历史文件缺失或校验失败 | `503` | 保留权益事实，记录可定位告警，允许恢复后重试。 |

有效性仅取迁移时固化到 `DigitalDownloadGrant` 的 `valid_until`、`max_downloads`、`download_count` 和不可变 `DigitalAsset`，不再读取已退出的 Shop 下载默认值、当前 ProductVariant 或已删除商品。`valid_until=null` 与 `max_downloads=null` 分别表示无到期日和不限次数，不得在迁移时推导新限制。

## 4. 并发与恢复

- 使用单条条件更新或行锁实现“校验并增加计数”，同一剩余次数不能被并发请求重复消费。
- 恢复时以 grant 主键、token、asset 校验和及已用次数幂等导入；已有较大下载计数不得被较小备份覆盖。
- 日志仅记录 token 的不可逆摘要和 grant ID，不记录完整 token、签名存储 URL 或敏感查询参数。
- 文件不一致时不自动改绑其他商品文件；由恢复流程按导出校验和修复。

## 5. 兼容退出门槛

维护前必须导出并核对文件、校验和、商品/变体/订单行关联、token、期限、最大次数和已用次数。未交付订单先完成签发或验证外部履约交接；兼容下载服务最终下线不在本轮。
