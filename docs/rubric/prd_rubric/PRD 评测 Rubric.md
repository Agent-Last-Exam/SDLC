# PRD 评测 Rubric

## 一、评价目标：只回答两个主要问题

本方案评价 Agent 是否按照指定要求，生成一份与 Golden PRD 业务内容一致的需求文档。评价分成两大类：**Schema 合规**和**Golden 内容一致性**。

第一类不仅检查标题、字段是否存在，还检查任务明确规定的验收条件、来源、优先级和修订规则。第二类检查 Golden 中该有的内容是否完整保留，以及候选是否新增、改错或自相矛盾。

### 规则出处

- **【任务规定】**：老板明确给出的 Schema、编号、AC、来源及 P0/P1/P2 定义。
- **【文献借鉴】**：原始论文或官方材料支持的评价属性、原子对齐与来源支持方法。
- **【本方案设计】**：具体检查组织、分数、分母、证据要求及结果解释。

## 二、固定 PRD Schema

**【任务规定】** 章号保持为 1、2、4、5、6，不擅自补第 3 章。花括号为填写提示，不是最终 PRD 应保留的文字。

```Markdown
# PRD：{标题}

版本：---
责任：产品
状态：需求范围与验收条件已定义

###（如果是修订，那版本号以及修订内容需要更新）

## 1. 业务背景与目标

## 2. 用户与场景
{受影响的用户类型及各自的典型任务}

## 4. 需求条目
{可按业务域分组}

### R{nn} · {标题}
- 来源：{引用 Instruction 原文}
- 优先级：{P0 | P1 | P2}
- 需求描述：{要做什么事情}
- 验收条件：
  - AC-{nn}-{m}：{可观察、可判定的条件，一条对应一个场景}

## 5. 范围与非目标
{本次交付包含什么，明确不做什么}

## 6. 其他
{其他上述未考虑的topic}
```

“如果是修订……”是条件说明，不要求原样保留该行。没有额外主题时，“其他”可以写“无”。章节中允许按业务域组织，但不额外要求某种文风、篇幅或业务域名称。

**【本方案解释，待确认】** 首次文档暂允许模板中的版本占位“\-\-\-”；修订必须更新实际版本标识并说明变化。编号稳定规则暂同时适用于 R 和其 AC；数字前导零不产生新身份，R1 与 R01 不得表示两个需求。保留这些解释的待确认状态，不把它们冒充新增的已批准规则。

## 四、第一大类：Schema 合规

### A1：结构与必填字段是否完整

**【任务规定】** 候选应包含 PRD 标题、版本、责任、状态，五个规定章节，以及每条需求的标题、来源、优先级、描述和验收条件。

**【本方案设计】** 按五组检查：

1. 文档标识：标题非空，版本符合首版或修订规则，责任与状态符合模板。
2. 章节结构：五个指定二级标题各出现一次，不卡死顺序，顺序合理即可，内容不是未填写的占位符。
3. 需求字段：至少一条 R，每条指定字段齐全且非空，优先级属于 P0/P1/P2。
4. AC 结构：每条 R 至少一个带编号且非空的 AC，归属于正确需求。
5. 当前编号：R 唯一，AC 完整编号唯一，编号合法，不因前导零而重复定义。

每组全部满足记 1，否则记 0；结构分是通过组数除以 5，再乘 100。每组都保留具体问题清单。零需求时第 3、4 组失败，不能让空集合默认通过。

这个分数只说明结构，不代表整个 Schema 已合规。来源不真实、AC 不可判定等问题由后面的检查继续判断。

### A2：一条 AC 是否对应一个可验收场景

**【任务规定】** 一条 AC 对应一个场景，且条件可观察、可判定。

**【文献借鉴】** S2 讨论需求的单一性和可验证性。\[S2\] 将其用于 AC 是本方案适配；不继续强制每条 R 只能一个功能，也不要求每个 AC 只能一个断言。

**【本方案设计】** 对每个 AC 分别判断：

- 场景是否单一：是否只描述一个适用场景，而非将正常、越权、超额等独立场景挤在一起。
- 条件是否可验收：读者是否知道在什么条件下，观察什么行为或结果，才能区分满足和不满足。

明确满足记 1，明确不满足记 0，证据确实不足以判断则记“无法判断”。分别报告单场景通过率和可验收通过率，不混成一个分数。

“退款后余额正确且交易状态更新”可以是同一场景的多个必要结果；“正常退款、超额退款和无权限退款都应正确处理”混合了独立场景。“权限处理正常”无法作为明确验收条件。

前提可以来自所在 R 和共享规则，不强制 AC 逐字重复。某条 R 没有 AC，由 A1 记录缺失；A2 显示“哪些 R 无 AC”，不能因为其他 AC 全部通过就宣称文档完整。AC 总数为零时，两项比例不计算。

### A3：Instruction 来源是否真实且支持需求

**【任务规定】** 每条需求的来源引用 Instruction 原文。

**【文献借鉴】** S7 的原子内容与来源支持思想说明了为什么“有引用”不等于“引用支持内容”。\[S7\] 原文不是 PRD 引用标准；下面的规则是本方案设计。

每条 R 检查引文是否存在于指定 Instruction，是否保留原意，是否支持所声称的业务来源。三者均满足记 1；缺引用、伪造、错文档或语义不支持记 0。没有提供 Instruction 或支持关系确有歧义时标“无法判断”。来源通过率按候选 R 统计。

允许必要空白归一化和分别定位多个原文片段，不允许把改写标成原话。候选不必引用与 Golden 相同的句子，但粗泛引文不能为新增的详细阈值或权限例外自动背书。若 Golden 包含这项细则而公开输入缺乏依据，应披露参考／任务输入缺口，而不是补造引文。

### A4：优先级是否符合 P0/P1/P2 定义

**【任务规定】**

- P0：去掉它，Business Brief 中某个目标无法达成，或引入功能不可用、数据错误、安全合规问题。
- P1：去掉它，目标仍能达成，但有明确的使用者必须多做正常操作（手工处理、多走流程）才能完成任务。
- P2：去掉它，目标照样达成，也没有具体的人需要因此多做事。

**【本方案设计】** 先用 Brief 确认 Golden 业务义务的预期标签，再比较已对齐候选的标签。正确记 1，错误、非法或漏写记 0；预期标签或对齐未明确则无法判断。不新增候选必填的“优先级理由”字段，Judge 在报告中给出现有材料依据。

报告已对齐义务的标签正确率，同时报告对齐数量占 Golden 义务总数的比例。完全遗漏的需求由 B1 检查，不得到优先级正确的信用；没有对齐对象时不计算正确率。

合并了不同优先级义务后统一写 P0，不代表每个义务都标对；按对应义务分别核查。一个义务拆成多条时，相关条目均需保留其确认标签，不因拆条增加该义务的权重。全部标 P0 不会自动满分，报告同时指出降级和无依据上调。

对候选无参考支持的新增需求，不伪造预期标签；由 B2 指出内容问题，并披露它没有获得 A4 标签正确的证明。

## 五、第二大类：Golden 内容一致性

### B1：从 Golden 检查候选，有没有漏写或改错

**【文献借鉴】** S1 将参考 PRD 拆解为原子需求，以 Rubric 判断生成文档是否满足要求。\[S1\]

**【本方案设计】** 在比较候选前，冻结 Golden 的实质检查点，覆盖背景目标、用户场景、需求行为、验收场景、范围非目标和其他已明确的决定。检查点保留主体、条件、动作、结果、否定及“已决定／假设／待确认”身份；不切到失去业务含义。

同一规则重复出现不重复计数。需求行为与验收场景可以分别检查，因为“支持一种能力”和“写明怎样验收”并不相同；来源字段和优先级由 A3/A4 检查，不重复放进内容分母。不构成业务约束的技术细节，不自动成为必须复现的唯一方案。

候选完整、等价地表达一个检查点才记 1。遗漏、只提主题、缺关键条件、缩窄／扩大业务含义或明确冲突均记 0，并区分原因；真正无法确定时标“无法判断”。

覆盖率是完整保留的检查点数除以 Golden 检查点总数，再乘 100。同时展示各内容类型和 P0 相关内容的遗漏，而不是只报一个平均比例。

S1 正文是二值满足公式，附录 C\.6\.2 另有 0/0\.5/1 提示。本文明确选择严格二值，是我们的口径选择，不把两者混称为论文统一分制。

### B2：从候选检查 Golden，有没有无依据新增

仅检查 B1 不够：候选可以写全正确内容，再额外加一条“管理员不受权限限制”，仍显得覆盖完整。

**【文献借鉴】** S7 将生成文本拆成原子事实，统计可靠来源支持的比例。\[S7\] 这里借鉴反向核验思想，不借用原任务的性能结果。

**【本方案设计】** 从候选全文抽取去重的实质断言，逐一检查 Golden 是否支持。等价表达或不增加业务义务的直接解释记 1；无依据新增、篡改或冲突记 0；参考含糊、矛盾或无法确定时标“无法判断”。忠实度是获支持断言数占候选实质断言总数的比例。

标题、同义重复和无新义务的说明不增加分母。新增功能、性能阈值、权限例外、依赖或必做流程都需要支持。仅作为备选且未写入交付承诺的建议可单列说明；加上“建议”两字但又写入强制 AC，不能逃避核查。

Golden 未写不等于现实中禁止；本指标只表示本次参考没有支持。Instruction 明确支持而 Golden 漏写时，应标参考缺口，不擅自给候选判错。

### 清晰度与全文一致性：对齐成立的条件，不再独立打分

**【文献借鉴】** S2 的无歧义性说明一个需求不能有多种实质不同的解释；S6 支持准则化评价及评测器可靠性核验。\[S2\]\[S6\] 下面怎样影响对齐由本方案规定。

- **清晰度条件**：候选含糊到允许多种业务含义时，不能确认等价。“适当处理配送”无法完整支持“失效时禁止成交”。明确缺了内容给对应点 0；确实不能判断缺陷与含义时保留未知，不逼模型猜。
- **全文一致性条件**：Judge 要读关联章节，不只搜索一个支持句。候选对同一条件同时写“允许”和“禁止”，B1 对应点不能判完整保留，B2 要保留冲突断言。
- **上下文条件**：不同角色、模式、版本下的不同规则不直接构成矛盾；共享定义和约束要一起读。

冲突结论要给两处原文并说明条件相同。没有发现冲突不等于证明全文绝对一致，仍需披露已检查范围和无法判定项。

## 六、评分报告怎样呈现

### 1\. 两大类内部报告分项，不拼一个总分

**Schema 合规报告**包括 A1 结构分、A2 两项 AC 通过率、A3 来源通过率、A4 标签正确率及对齐范围、A5 历史检查结果。**Golden 一致性报告**包括 B1 覆盖率、B2 忠实度、差异证据和全文冲突。

这些指标的分母不同，不相加、不求平均。当前没有经过校准的综合权重或及格线。安全、数据、P0 目标等已确认问题先展示，不能被其他正确项的数量遮住。

同一缺陷可影响多个相关检查，但共用问题编号，不再额外扣“严重度分”。百分比使用原始计数计算，最后显示时保留两位小数。

### 2\. 明确零分、空集合和未知

确定文档缺字段、引用造假或内容错误，可以判不通过；文件无法读取或模型调用失败，属于过程失败，不给候选伪造零分。

对应指标有无法判断项时，暂不发布该指标完整数值，保留已确认的结果、分子分母信息和未知数量，不删除困难项重新归一化。明确没有适用对象时不计算比例，不当作满分。

可读取候选无业务内容且 Golden 非空时，B1 为 0；候选没有实质断言时 B2 不计算。零需求时 A3 不计算，A1 对应组不通过；零 AC 时 A2 不计算且列出缺失；无对齐义务时 A4 不计算。Golden 为空不是有效内容评测参考。

### 3\. 不把完成评测写成通过

- Schema 全部适用规则有证据通过，才可以说 Schema 合规；A1=100% 本身不够。
- B1=B2=100%，判断完整且没有未解决的业务矛盾，才可说与冻结 Golden 的业务内容一致。
- 两大类全部适用检查通过且无未决参考问题，才可以说满足本 Rubric 的全部要求。仍不代表软件实现正确或达到生产发布标准。
- 已确认反例即足以说明相应要求不满足；同时存在未知时仍保留这个反例，不把问题藏在“整体无法判断”后面。

## 七、Saleor 教学例子与案例

以下借用 Saleor 业务方向，候选表现和数字均为合成教学材料，不是实际模型结果。

| 候选表现                                         | 怎样判断                                                               |
| ------------------------------------------------ | ---------------------------------------------------------------------- |
| 结构字段齐全，但目标只写“优化平台”             | A1 可能通过；若未表达 Golden 的具体目标，B1 对应点失败，不再另给 K1 分 |
| 明确写“超级管理员可绕过密码限制”，参考禁止绕过 | B1/B2 记录规则反转，不因为句子流畅而加独立清晰度分                     |
| 只写“支持库存配送”，未表达库存与运费分别判断   | B1 未完整保留必要规则                                                  |
| 一个 AC 混写三个独立身份场景                     | A2 单场景检查失败；B1 仍按实际写出的内容判覆盖                         |
| AC 写“权限处理正常”                            | A2 可验收检查失败；也不能靠这句话证明覆盖了具体拒绝场景                |
| 一处禁止绕过，另一处允许同一身份绕过             | B1 不能只取正确句，B2 保留冲突，报告给出两处原文                       |
| 引用 Instruction 里不存在的“三秒返回”          | A3 来源失败，并由 B2 检查是否新增承诺                                  |
| 参考没有成功指标要求，候选也没写                 | 不构成独立缺陷，不再要求 K7 栏目或评分                                 |

假设 Golden 有 12 个检查点，候选完整保留 10 个，遗漏 1 个、改错 1 个，则 B1=83\.33%。候选有 11 个去重断言，其中 10 个获支持、1 个冲突，则 B2=90\.91%。这两个比例不是可平均的“及格分”，需要同时呈现具体错误。

反向核查的必要性：候选写全 12 个点后又添加一个无依据功能，可以出现 B1=100%、B2=92\.31%；不能因覆盖完整就宣布内容一致。

## 八、文献借鉴与自有设计边界

### S1：参考 PRD 的原子需求对齐

Steering LLMs via Scalable Interactive Oversight，arXiv:2602\.04210v2。原始入口：`https://arxiv.org/html/2602.04210v2`。

借鉴 §4\.1、附录 C\.6 和 C\.8 的参考 PRD 原子化与 Rubric 对照，用于 B1。本文的清单冻结、严格语义等价、未知处理和报告分组是本方案设计；不照搬其网站模块、模拟器或实验性能，也不混淆正文二值与附录分档。

### S2：单一性、可验证性与无歧义性

From issue titles to requirements: an empirical study of large language models and prompt engineering strategies，Requirements Engineering，2026。DOI：`10.1007/s00766-026-00462-z`；入口：`https://link.springer.com/article/10.1007/s00766-026-00462-z`。

借鉴 §3\.3 中的三项内在需求质量属性，用于 A2 和语义对齐条件。原研究以独立 LLM 按 1–5 分评分，并人工抽样验证。**本版既不照搬其 1–5 分，也不保留旧 0–3 分；这些属性融入通过／不通过的任务检查。** 由需求属性迁移到 AC 场景及 Golden 对照，是我们的适配。

### S7：原子断言与来源支持

FActScore: Fine\-grained Atomic Evaluation of Factual Precision in Long Form Text Generation，EMNLP 2023。DOI：`10.18653/v1/2023.emnlp-main.741`；入口：`https://aclanthology.org/2023.emnlp-main.741/`。

借鉴原子事实及可靠来源支持比例的思想，用于 B2，也帮助解释 A3 的来源支持关系。原任务是长文本事实性，不是 PRD 需求评价；本文的 Golden 和 Instruction 角色及具体判据是自有设计。核验范围为官方摘要，不声称已重读 PDF 全文或复现性能。
