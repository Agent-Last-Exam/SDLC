  - 公开 Target、Patch、Oracle 或隐藏测试；
  - 公开完整技术方案；
  - 公开唯一正确的模块分解；
  - 用业务沟通记录伪装参考答案；
  - 用 Query 直接规定候选 PRD 应该如何写。

  - 调查成本是否合理；
  - 是否需要多个仓库或多个组件联合调查；
  - 是否只能通过运行系统才能确认；
  - 是否存在版本、权限或路径歧义。

  如果证据不足，不能简单分类为“让 Agent 调查”，应标记为：

  - `not_recoverable_from_base`
  - `requires_public_decision`
  - `requires_runtime_evidence`
  - `out_of_scope`

  ### E. 任务难度

  为每个信息分配判断是否会：

  - 过度帮助 Agent；
  - 造成不必要的猜题；
  - 让任务变成纯文本改写；
  - 让任务无法完成；
  - 让不同合理答案被错误视为错误；
  - 让后续 Rubric 无法公平评价。

  本步骤允许：

  - 读取第二步 worklog；
  - 只读调查 Base；
  - 更新 private/worklog.md；
  - 在 worklog 中形成信息分配矩阵和待确认项。

  本步骤禁止：
