# Saleor 商家平台升级

我们希望对现有商家平台做一轮升级，以支持更多外部应用接入和更灵活的经营方式，同时保持存量商家的日常业务连续。

本轮重点是改善商家对应用扩展和故障的管理；支持全部用户使用密码、仅顾客使用密码及仅依赖外部身份等登录选择；让库存管理更直接地遵循仓库与销售渠道的关系，并让外部运费计算更加可控。存量商家应能保留现有经营方式，再逐步切换。

同时，我们希望将礼品卡纳入统一的交易与退款管理，改善交易查询及经营信息维护，并提升内容处理、外部图片、搜索和应用通知的可靠性。外部应用应能按需接收相关数据变化，存量接入有过渡安排。已经正式弃用的内置支付和旧数字内容接口可以退出，但需保护已有交易、资产及相关业务的延续。

工作区已提供本次迭代的 Base 版本。请自行阅读其中的代码、文档、配置和测试，理解现有系统与工程约束，调查用户、业务流程、接口消费者及历史数据，推导完整需求，形成 PRD 和技术方案。方案须覆盖核心 API 与商家 Dashboard 的配套变化。不新建顾客 Storefront、原生 App 或第三方支付、身份产品。具体功能拆分、交互、业务边界细化和技术实现由你提出。

升级允许维护窗口，需要保护存量账号、订单、交易和应用接入，处理受影响的安全、兼容与数据迁移问题，并具备恢复及交付后验证安排。

## 本次交付范围

先形成 PRD、前后端技术设计、接口契约和完整目标接口描述。完整交付流程在设计后继续进行测试设计、功能开发、本地部署与 QA，并按测试结果进行有界修复。

具体输入输出路径、角色职责、交接与停止要求见当前角色指令；文档字段和格式见对应模板。只执行当前阶段指定的工作：文档阶段完成设计，开发阶段实现功能并验证，部署和 QA 阶段交付本地测试环境及测试结果。以提供的 Base 源码与公开输入为起点。
